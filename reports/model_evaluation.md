# Revenue-decline model: evaluation

Generated by `src/ml/evaluate_revenue_decline.py`. Proof of concept only; not investment advice.

## Conclusions

- walk_forward: the 5-ratio model has balanced accuracy 0.50, 95% interval 0.25-0.78 (permutation p = 0.532), not distinguishable from chance; it is no better than the seasonal rule (0.50, p = 0.965) on 15 test rows with 6 declines.
- unseen_company: the 5-ratio model has balanced accuracy 0.53, 95% interval 0.32-0.74 (permutation p = 0.438), not distinguishable from chance; it is worse than the seasonal rule (0.77, p = 0.020) on 31 test rows with 8 declines.
- walk_forward_unseen_company: the 5-ratio model has balanced accuracy 0.69, 95% interval 0.46-0.93 (permutation p = 0.129), not distinguishable from chance; it is better than the seasonal rule (0.50, p = 0.806) on 15 test rows with 6 declines.
- Multiple tests: 9 model/scheme combinations were tested; at the 5% level about 0.5 would fall below 0.05 by chance alone. 1 did, 0 of them with p <= 0.01, which chance rarely produces. A single result between 0.01 and 0.05 is weak evidence.
- A seasonality-free target (next quarter vs the same quarter a year earlier) would have only 9 labels with 0 declines in this data: it needs a longer history.
- Overall: there is no evidence that the model predicts revenue declines better than chance. Treat its output as an experimental research signal only, never as a risk score or investment advice.

## Target

- `Next_Period_Revenue_Decline`: 1 if the next reported quarter's revenue is lower than the current quarter's; 0 otherwise. Only transitions 70-110 days apart are labelled.
- Horizon: next reported quarter (about 3 months).
- Features use only the current quarter's statements. Training rows are limited to labels already known when the test rows' figures became available. Filing dates are not available, so period-end dates are used; statements are published weeks later, so this is an approximation.

## Models

- `majority_baseline`: Always predicts the most common training label.
- `seasonal_baseline`: Majority training label for quarters ending in the same calendar month (seasonality only).
- `logreg_5_ratios`: Proof-of-concept model: 5 ratios, logistic regression.
- `logreg_margins`: Same model with the two margin ratios only.

## Notes

- Minimum training rows: 10; a test row is skipped when its training set is smaller or has only one class (early dates cannot be evaluated).
- `validate_company_wise.py` trains on other companies at any date, including dates after the test rows; `unseen_company` reproduces that setup for comparison, the stricter schemes do not.
- `validate_date_grouped.py`, `train_revenue_decline_model.py` and `explain_revenue_decline.py` split on a date boundary but do not hold back labels that are not yet observable (e.g. 2025-12-31 labels use March 2026 revenue while NVDA's 2026-01-31 rows are in test). `walk_forward` does.
- In the time-aware schemes the seasonal rule usually scores 0.50 because the data has no earlier December quarter whose outcome was already known at the first December test date, so it cannot learn the December pattern yet. This reflects the short history, not an absence of seasonality (see the decline-rate table).
- With this little data, a single train/test split (as in those scripts) can swing by 0.25 balanced accuracy from one test case; use the pooled results above.
